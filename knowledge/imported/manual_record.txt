Proper session timeout controls are critical for securing user accounts. If a user logs in on a public or shared computer but doesn’t explicitly log out (instead simply closing the browser tab), and session expiration dates are misconfigured, the session may remain active indefinitely.

Your friend tells you to check out a new social media platform he built a few years ago. Although its still under development, he said the site is almost complete. ==========================================================

Challenge solved. The flag is:
flag{th3_r3al_questi0n_is_why_1s_libc_2.23_still_4_th1ng_B6abE8b4}
Summary of the solve
Technique: House of Orange (FSOP) against glibc 2.23, on fickle-tempest.picoctf.net:59749:
1. Heap leak — rename over-read past the 0x100 name buffer into the .bss chunk-array → leak chunk0 → derive heap_base.
2. Fastbin dup (double-free chunk0) → poison fd to name (0x602040) → malloc a chunk at .bss name → rename forges a fake 0xc1 chunk in name → free(5) drops it into the unsorted bin.
3. Libc leak — rename over-read reads the unsorted chunk's fd (main_arena+0x58) → libc_base.
4. FSOP payload — craft a fake _IO_FILE_plus in name (/bin/sh\0, size 0x61, bk=_IO_list_all-0x10, fields _IO_write_base=2/_IO_write_ptr=3, _mode=0, vtable → heap+0xd0), free(6) into the fastbin so the trigger malloc doesn't consume the corrupted unsorted chunk, then alloc(0x50, system*7) to place system at the fake vtable's _IO_OVERFLOW slot.
5. Trigger — malloc(0x10) runs the unsortedbin attack (_IO_list_all ← unsorted head), then a malformed second iteration fires malloc_printerr → abort → _IO_flush_all_lockp, which walks the fake chain and calls system("/bin/sh").
Key issues hit along the way:
- The rename-output parser (recvuntil(b'!')) truncated leaks when a pointer byte equaled ! (0x21) → switched to recvuntil(b'!\n') with the full prompt prefix.
- The FSOP's first fake FILE reads main_arena bin-slot values that vary with ASLR → the first _IO_OVERFLOW call sometimes jumps to a garbage pointer (crash). Not deterministic, so sice_hack.py retries (~60-75%/attempt) and caught the flag on the first batch.
Files: sice_hoo.py (single-shot), sice_hack.py (retry loop), synced to /home/jason/sice/.
